# Product Specification

## 产品定位

目标是将 DeepTutor 的个性化学习上下文与 OpenMAIC 的多模态课堂生成、互动、编辑和导出能力组合为一条学习路径：学习者带着明确的学习需要进入课堂，完成互动后能回到自己的学习记录继续学习。

当前工作区不是单体产品。`DeepTutor/` 与 `OpenMAIC/` 保持独立部署、依赖和 Git 历史；根目录 harness 只定义逐步融合的合同、验证和证据。

## 融合方式与当前阶段

融合不是让一个应用读取另一个应用的内部文件或浏览器存储，而是通过版本化的最小数据投影和应用服务边界传递必要信息。

```text
DeepTutor 的学习观察
    ↓ 最小化、经授权的教学上下文
集成适配层（版本、身份、授权、审计、错误处理）
    ↓ 课堂请求与结果契约
OpenMAIC 生成、播放和导出互动课堂
    ↓ 结构化学习结果
DeepTutor 的学习记录与后续辅导
```

F01 是这条路径的离线演示切片：F01 在 DeepTutor 内以脱敏 Demo 学生 A/B 推导教学上下文。F02 曾在 OpenMAIC 服务端消费人工审阅后的最小会话投影，其离线 A/B 演示 Demo 已随 F50 退役，不再影响课堂生成。它们没有真实登录、真实学生数据、自动同步或结果回写。

下一阶段若要形成真实闭环，必须由新 feature 明确授权的 Profile API、身份映射、课堂结果契约和回写规则；不能把 F01/F02 的 Demo 投影当作生产实现。

## 问题与用户

- 学习者需要把长期学习目标、薄弱点和课堂练习连成一条连续路径，而非在辅导工具与内容生成器之间手工搬运信息。
- 教师、助教和课程设计者需要生成可调整、可互动且能说明差异化依据的课堂。
- 首要结果是：用户能理解当前课堂为何这样生成、正在进行什么、结果保存在哪里，以及失败后如何恢复。

## 可复用能力

| 来源 | 现有能力 | 在融合中的职责 |
| --- | --- | --- |
| DeepTutor | 学习工作区、知识库、记忆、会话、智能体能力和多用户边界 | 提供经授权的学习上下文、长期学习记录与后续辅导。 |
| OpenMAIC | 课堂生成、场景/动作编排、回放、测验/PBL、编辑、媒体和导出 | 生成、交付和编辑多模态课堂。 |
| 集成适配层 | F01 的离线 Demo 适配已验证；F02 演示 Demo 已退役；生产形态尚未建立 | 约束最小投影、版本、身份/授权、调用、错误和审计。 |

## 交付原则

- 以 feature 合同逐项交付：先验证可观察用户结果，再扩大到真实身份、数据或回写。
- 不把模型生成、关键词命中或单次课堂对照表述为教学正确或真实学习效果。
- 中文为首要体验语言，同时保持两个上游既有国际化能力。
- 真实用户数据、外部 AI 调用、持久化迁移和跨应用回写必须有单独的最小数据、授权、兼容与验证设计。
