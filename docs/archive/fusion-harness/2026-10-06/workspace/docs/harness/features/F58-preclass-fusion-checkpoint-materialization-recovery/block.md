# F58 Block Record

## Status

- Feature: `F58-preclass-fusion-checkpoint-materialization-recovery`
- Status: `blocked`
- Date: 2026-09-21
- Blocking decision: F58 is paused as the active workstream and is not eligible for `passing`.

## Why F58 is blocked

F58 produced useful downstream repairs for formal checkpoint/remediation pair identity, scene materialization traceability, and export metadata preservation. However, the work direction is not the current primary product question.

The current priority is not only to prove that a formal checkpoint/remediation pair can survive OpenMAIC materialization and export. The more fundamental pre-class Fusion question is:

```text
Prove that the classroom generated by OpenMAIC actually used the teaching context returned by DeepTutor.
```

F58 currently focuses on the downstream OpenMAIC chain:

```text
generatedOutlines
  -> scene builder
  -> classroom store
  -> recovery/export manifest
```

That chain is relevant, but it does not by itself prove the upstream pre-class Fusion semantic roundtrip:

```text
OpenMAIC semantic request
  -> DeepTutor pre-class teaching context
  -> FrozenLessonGenerationContext
  -> OpenMAIC outline/content generation
  -> classroom evidence linked to that context
```

## Independent review result

Independent read-only review returned `FAIL`; final passing was also blocked by missing fresh browser/manual export evidence.

Key findings:

1. Existing tests mostly cover outline-level materialization guards, not full SSE/browser/content/actions/store/recovery/export parity.
2. Scene Catalog validation is still shallow and does not fully compare entries against persisted outlines and binding metadata.
3. `materializationLedger` records a planned state, but not complete per-scene content/action/store/export transitions or failures.
4. Store validation happens late and does not persist durable materialization failure diagnostics.
5. Export validation still relies on browser state and lacks a fully authoritative server-session/catalog cross-check.
6. A fresh formal Fusion browser run and `.maic` export evidence have not been produced.

## New active direction

Work shifts to F59:

```text
F59-preclass-fusion-semantic-context-roundtrip-proof
```

F59 must prove the semantic roundtrip:

1. OpenMAIC constructs and sends the correct teaching semantic request to DeepTutor.
2. DeepTutor returns authorized/versioned teaching context.
3. OpenMAIC freezes that context as `FrozenLessonGenerationContext`.
4. The frozen context is actually consumed by outline/content generation.
5. Generated classroom artifacts can be traced back to the DeepTutor context without storing sensitive learner data.

## Unblock condition for F58

F58 may be resumed only after F59 establishes the upstream semantic context proof, or if a later export/materialization regression requires continuing the downstream pair-preservation work.

To mark F58 passing in the future, the team must still provide:

- fresh formal Fusion browser run evidence;
- `.maic` export manifest audit showing both formal pair members and binding metadata;
- recovery evidence;
- ordinary/LAN/history non-regression evidence;
- independent read-only review returning `PASS`;
- a passing or explicitly waived harness gate with documented reason.
